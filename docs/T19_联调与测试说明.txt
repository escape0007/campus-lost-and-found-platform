二、主程序的完整链路
1. 注册并登录；人工浏览或筛选公告，不依赖匹配建议也可继续。
2. 打开拾获公告，提交 10–1,000 个 Unicode 字符的私密证据，可关联自己仍为 Open 且未被预留的丢失公告。禁止认领自己发布的物品。
3. 双方在认领记录内提交 1–1,000 字的私密说明。不同认领案件相互隔离，普通审核角色没有全局读取私密案情的权限。
4. 拾获人填写理由批准或拒绝 Pending 认领。批准原子写入拾获公告和关联丢失公告的唯一预留，其他 Pending 转 Held，禁止新增认领；Held 不能直接批准。
5. Pending/Held 可以由认领人撤回。已批准认领只能经指定复核员处理争议取消；取消清理确认和预留，其他 Held 恢复 Pending，再按所有未结束认领重算公告状态。
6. 交接双方各自确认实际归还。一次确认仍为 Awaiting collection，审核员不能代替双方。两次确认后原子提交拾获公告 Returned、关联丢失公告 Closed、其他相关认领 Item returned，退出发现与新提醒。
7. 争议暂停归还确认。复核员先领取任务，才能读取该案件；释放或全部处理完成后立即撤销案件权限。恢复领取会使旧确认失效并开启新的确认轮次。归还后举报保留 Returned 和历史。
8. 举报公告可经指定复核隐藏。隐藏不会抹除历史，普通发现及后续操作会重新检查当前状态。
9. 前端提供认领/审核列表、私密会话、双确认、举报及复核入口。操作超时保留请求标识，人工重试不会重复写入；写入成功后的展示错误明确显示“已保存”。退出后清理私密界面内容。

五、审核员配置与本地运行
默认启动没有预置账号或审核员；学生注册接口不能设置角色。先通过正常注册建立所需账号，停止服务，再由本机操作者显式配置：
APP_MODERATOR_USERNAMES=registered_username java -jar campus-lost-found-0.1.0.jar
多个账号用逗号分隔。仅可指定已存在且有效的账号；未知账号或同时授予/撤销同一账号会使启动失败，整批配置回滚。
需要撤销时由操作者使用 APP_MODERATOR_REVOKE_USERNAMES=registered_username 启动；同时撤销该账号所有有效案件分配。操作有账号审计记录。配置不创建默认密码，也不自动注册账号；不要把真实凭据写进仓库。
角色授予仅允许进入复核队列，仍需逐案领取；不能领取涉及自己的案件。DISMISS 记录不予处理并结束对应争议；RESUME_COLLECTION 明确恢复已批准的争议案件并要求重新双确认；CANCEL_APPROVAL 撤销批准与预留。全部相关举报处理完才解除争议。
本次仅本机回环运行，没有部署公网后端。旧 T13 数据库再次启动会添加工作流表，保留已有公告、账号和照片。升级前仍应保存原数据副本。
