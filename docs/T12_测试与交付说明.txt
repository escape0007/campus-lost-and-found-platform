T12「匹配排序与理由」实现说明
日期：2026-10-25（Asia/Macau）
依据：Task2 SRS v1.2（2026-10-18）REQ-1.5、AT-05 的排序规则、PERF-03；T06 的 UC05。
基线：T11 的账号、公告和多条件筛选。认领、归还和审核流程仍未实现。匹配只读取已经提交的公告状态、隐藏标记和有效预留，不读取私人证据或消息。本文不把自动化结果记为 AT-05 验收通过。

一、已实现
1. 登录后在公告详情查看建议。只比较 Open、未隐藏、没有有效预留、类型相反的公告。Claim under review、Awaiting collection、Returned、Closed 和隐藏项不参与。
2. 排序固定为：相同类别、共同词语、地区接近程度、日期接近程度，然后按公告 ID 升序。配置版本 t12-2026-10-25。相同地区高于相邻地区；相邻关系为图书馆—教学楼、教学楼—食堂、食堂—宿舍、宿舍—运动场。日期按同一天、3 天内、7 天内分档。
3. 每条建议给出公开字段理由和置信度。近似日期、未指定类别、未指定地区、不同类别、没有共同词语、地区较远或日期超过 7 天会降低置信度，但不改上面的排序。建议不能证明归属。
4. 用户忽略一对公告后，该用户永久不再看到这一对。材料版本变化或公告再次成为 Open 也不恢复。其他用户不受影响。
5. 建议在读取时按当前状态重算。发布、实质编辑，以及已提交状态重新成为 Open 之后，下一次读取在 10 秒内使用新状态。学生不能把 Returned 或 Closed 重开；测试用已提交的状态变化模拟流程结束后的恢复。
6. 一次最多返回 20 条，并给出符合条件的总数。匹配失败时保留公告和人工搜索，不编造建议，页面可以重试。

三、启动与检查
解压完整交付包，进入 app 文件夹。Windows 在该目录执行 启动T12.ps1；macOS 双击 启动T12.command。也可执行：
java -jar campus-lost-found-0.1.0.jar
启动后打开 http://127.0.0.1:8080/app/ 。先注册，再登录，打开一条公告查看 Suggested matches。没有预置账号。
若 8080 被占用，可加参数 --server.port=8081，再打开对应端口。
保留同目录 data 文件夹可保留本地数据；按 Ctrl+C 停止。交付包不包含演示数据库，首次启动为空。
从源码重建：进入 source/backend，执行 mvn clean package。该命令会先跑测试，再生成可执行 JAR。程序只绑定本机地址。
