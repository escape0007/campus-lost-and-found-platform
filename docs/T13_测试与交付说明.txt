T13「新匹配提醒」实现说明
日期：2026-10-25（Asia/Macau）
依据：Task2 SRS v1.2（2026-10-18）REQ-1.6、AT-06 的偏好、去重和补发规则、PERF-03 的 60 秒可见要求；T06 的 UC06。
基线：T12 的账号、公告、筛选和建议。认领、归还和审核仍未实现，因此没有私人案件模块。本文说的“案件仍可访问”是指提醒不会拿走公告、搜索和建议，已有提醒也继续可读。本文不把自动化结果记为 AT-06 验收通过。

一、已实现
1. 登录后可在「提醒」页选择「新匹配提醒」或「自行查看」。注册时默认为新匹配提醒。待确认状态记在接口的 defaultConfirmation=PENDING，页面不展示需求说明。
2. 手动模式不生成新提醒。已经生成的提醒仍可打开，链接显示公告当前状态，不会把公告重新打开。搜索和建议保持可用。
3. 重新开启时，开启顺序记为当时的提交计数，不把计数加一。只有提交顺序严格晚于这次开启的变更才会生成提醒。手动期间的事件，以及事后按原事件重放的延迟重试，都不会补发。判断使用事件保存的 trigger_order，不用重试当时的时钟。
4. 同一用户、同一对丢失/拾到公告、双方实质版本只保留一条提醒。实质版本只随标题、类别、发生日期、地区或描述变化。只改照片、近似日期或时间戳的更新种类是 NOTICE_UPDATED，不产生新版本，也不新发提醒。
5. 提醒在公告事务提交之后写入。失败不回滚公告；下次打开提醒列表会重试尚未投递的事件。合格提醒在本次自动化中于 60 秒内可读。
6. 提醒只发给这两条公告的作者。置信度低于 70 的相反类型不发提醒。70 这个界限来自方案 t13-2026-10-25，排序仍用 t12-2026-10-25。它是团队方案，不是已经校准的 AT-06 通过记录。忽略一对后，该用户不再收到这一对的新提醒。
7. 无效偏好返回 422，过期版本返回 409，原来的选择保持不变。

三、启动与检查
解压完整交付包，进入 app 文件夹。Windows 在该目录执行 启动T13.ps1；macOS 双击 启动T13.command。也可执行：
java -jar campus-lost-found-0.1.0.jar
启动后打开 http://127.0.0.1:8080/app/ 。先注册，再登录，打开「提醒」。没有预置账号。
若 8080 被占用，可加参数 --server.port=8081，再打开对应端口。
保留同目录 data 文件夹可保留本地数据；按 Ctrl+C 停止。交付包不包含演示数据库，首次启动为空。
从源码重建：进入 source/backend，执行 mvn clean package。该命令会先跑测试，再生成可执行 JAR。程序只绑定本机地址。
