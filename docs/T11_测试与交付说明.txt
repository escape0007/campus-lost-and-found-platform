T11「人工搜索与多条件筛选」实现说明
日期：2026-10-25（Asia/Macau）
依据：Task2 SRS v1.2（2026-10-18）REQ-1.4、AT-04 的浏览规则、CAP-03；T06 的 UC04。
基线：T10 复核后的账号、发布与无筛选浏览。本说明不把自动化结果记为 AT-04 验收通过。

一、已实现
1. 登录后可直接浏览可用公告，也可同时使用关键词、Lost/Found、类别、发生日期范围、校园区域和 Open only。
2. 默认结果含 Open 与 Claim under review。Open only 单独排除 Claim under review。Awaiting collection、Returned、Closed、hidden 和有效预留不进入可用列表。
3. 关键词按标题和描述做不区分大小写的包含匹配，中文和英文都可检索；空格分开的词要同时命中。% 和 _ 按字面处理。
4. 排序为发布时间新到旧，公告 ID 决胜。默认每页 20 条，允许 1–50，超过 50 拒绝。翻页继续带上已应用的条件，并按当前状态重新查询。
5. 无匹配是正常空结果，并提供调整筛选和“Browse all available”。查询失败时保留筛选并可以重试。打开公告时读取当前状态。
6. 我的公告仍显示作者自己的未隐藏记录，包括已归档记录。可用列表的筛选不会把这些记录放回公共浏览。

三、启动与检查
解压完整交付包，进入 app 文件夹。Windows 在该目录执行 启动T11.ps1；macOS 双击 启动T11.command。也可执行：
java -jar campus-lost-found-0.1.0.jar
启动后打开 http://127.0.0.1:8080/app/ 。先注册，再登录。没有预置账号。
若 8080 被占用，可加参数 --server.port=8081，再打开对应端口。
保留同目录 data 文件夹可保留本地数据；按 Ctrl+C 停止。交付包不包含演示数据库，首次启动为空。
从源码重建：进入 source/backend，执行 mvn clean package。该命令会先跑测试，再生成可执行 JAR。程序只绑定本机地址。
