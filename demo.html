认领人提交 10–1,000 个字符的文字证据，并可关联自己仍为 Open、未被预留的丢失公告。双方在该案件内补充私密说明。

决定者 · 拾获人

批准一条认领，
为交接保留物品。

拾获人核对证据，填写理由批准或拒绝 Pending 认领。批准后，系统同时预留拾获物品和已关联的丢失公告。

  • 同一物品及关联丢失公告仅允许一条有效批准。
  • 其他 Pending 认领转为 Held，不能直接批准。
  • 批准表示等待交接，尚未确认实际归还。

双方当事人 → 指定复核员

有争议时暂停，
由指定人员复核。

完成前提出争议会暂停归还确认。复核员必须先领取案件，才可读取该案件的私密信息；释放或全部处理完成后立即撤销权限。

  • 示例中第一次单方确认后出现交接争议。
  • 明确恢复领取后，旧确认失效，开启新确认轮次。
  • 复核员不能替双方确认归还，也不代表校方介入。

真实验证路径 / Review

  1. 提出争议 · 暂停确认
  2. 领取任务 · 指派案件访问
  3. 恢复领取 · 旧确认失效
  4. 处理完成 · 撤销案件权限

已批准认领的取消须经指定复核员处理；取消后释放预留，按剩余认领重新计算公告状态。

交接双方 · 独立确认

双方各自确认，
才记录成功归还。

双方实际交接后，各自在本地应用确认。一次确认仍是 Awaiting collection；相关争议全部处理完并完成两次确认后，系统原子记录归还结果。

  • 拾获公告 → Returned；关联丢失公告 → Closed。
  • 其他相关认领 → Item returned。已归还物品退出发现与新提醒。
  • 归还后举报保留 Returned 结果与历史。

03 / Get the full application

下载应用，在本机走完流程。

Java · 本地运行

课程仓库是当前源码的主要来源。GitHub Pages 提供项目展示与静态演示，完整的账号、数据保存、认领和复核由本地 Java 服务处理。

下载运行包 ZIP ↓下载课程源码

运行包约 27.6 MB，包含已构建 JAR、源码和联调说明。v0.1.0-t19 课程演示预发布由本次个人镜像提供；课程仓库仍是主要源码来源。

需安装 JDK；从源码构建还需 Maven。编译目标 Java 21，本次实测 JDK 25.0.2、Maven 3.9.16。Java 21 运行时尚待单独验证。

T19 联调、复核员配置与限制 →

方式一：解压运行包后，在解压目录运行

cd app
java -jar campus-lost-found-0.1.0.jar

方式二：下载课程源码，在项目目录构建

cd backend
mvn clean package
java -jar target/campus-lost-found-0.1.0.jar

服务启动后打开 http://127.0.0.1:8080/app/。

先注册虚构测试账号再登录；默认没有账号或审核员。需体验复核时，按 T19 文档为已注册账号配置角色并逐案领取。账号不代表校园身份认证。

从 app 或 backend 启动时，数据保存在该目录下的 data/。保留此目录可继续本地记录；停止服务使用 Ctrl+C。
